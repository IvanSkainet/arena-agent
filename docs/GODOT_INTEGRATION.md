# Godot Game Production via Skainet Bridge

Архитектурное руководство по разработке игр на Godot Engine через **Skainet Bridge** в условиях изолированных песочниц (Arena.ai Agent Mode, Claude Code, Codex).

---

## 1. Контекст проблемы и ограничения среды

При попытке автономной разработки игр внутри песочниц AI-агентов (например, Arena.ai) возникают три фундаментальных барьера:

1. **Лимит снапшота Workspace (128 MB):**
   Движок Godot, экспортированные шаблоны, 3D-модели (.gltf / .obj), текстуры и звуковые библиотеки превышают лимит 128 MB. Попытка распаковать Godot в `/home/user` приводит к немедленной обрезке и поломке снапшота.
2. **Отсутствие GPU и X11:**
   В песочнице нет графического ускорителя (GPU) и запущенного дисплейного сервера X11/Wayland. Агент не может открыть окно игры и визуально оценить геймплей.
3. **Изоляция сети:**
   Песочница не может принимать входящие соединения без специализированных прокси.

---

## 2. Архитектура решения: Сквозной мост (Bridge + Host)

Skainet Bridge разделяет разработку на два контура:

```
+------------------------------------+           +------------------------------------------+
|       Arena.ai / Cloud Agent       |           |          Operator Host Machine           |
|                                    |           |                                          |
|  - Написание GDScript & шейдеров   |  Bridge   |  - Установленный Godot 4.x (.exe / ELF)   |
|  - Логика Spec-Kit (T0..Tn)        |  API/MCP  |  - Реальный GPU (NVIDIA / AMD / Apple)   |
|  - Headless тесты и валидация кода | --------> |  - Полное дисковое пространство (>100GB)|
|  - Протокол turn_request/complete  |           |  - Запуск сцен и захват кадров (CDP/Win) |
|  - Потребление диска: 0 MB         |           |  - Хранилище: ~/arena-bridge/projects/   |
+------------------------------------+           +------------------------------------------+
```

## 3. Схема взаимодействия с `godot-game-production-skill`

При использовании скилла [godot-game-production-skill](https://github.com/StanislavSmetaninSSM/godot-game-production-skill) агент действует по следующему регламенту:

### Шаг 1: Инициализация проекта на хосте
Агент не распаковывает бинарники Godot в песочницу `/home/user`. Вместо этого проект создается на хосте через файловый API моста:
- Путь на хосте: `~/arena-bridge/projects/<project_name>/`
- Агент отправляет `project.godot` и базовую структуру сцен через эндпоинты `/v1/files/write` или MCP-инструмент `write_file`.

### Шаг 2: Headless валидация и автоматические тесты
На хосте через Bridge Exec API (`/v1/exec` или MCP `exec`) запускается Godot в headless-режиме:
```bash
godot --headless --script res://tests/run_tests.gd
```
- Проверяется компиляция всех GDScript-файлов;
- Прогоняются модульные тесты игровой логики;
- Результаты (JSON/stdout) возвращаются агенту в песочницу за доли секунды.

### Шаг 3: Захват визуальных референсов и кадров геймплея
Для визуальной валидации (чек-лист `CORE_LOOP`):
1. Игра запускается на хосте на 3-5 секунд:
   ```bash
   godot --fixed-fps 60 --duration 5 res://scenes/main.tscn
   ```
2. Мост делает скриншот окна игры через `/v1/desktop/screenshot` или извлекает PNG, сохраненный движком в `user://screenshots/`.
3. Агент анализирует скриншот и принимает решение о визуальной корректности сцены, геометрии и освещения.

### Шаг 4: Генерация графических ассетов
Если у агента нет специфичных инструментов генерации (например, Imagen от Codex), агент использует встроенные возможности среды (Arena.ai `generate_image`, `image_search`, или локальные скрипты генерации на хосте через Blender/Pillow) и сохраняет текстуры напрямую в `res://assets/` на хосте.

---

## 4. Спецификация файлов обмена

Для интеграции с игровыми демонами (включая файловый протокол по типу Book of Eternity):
- `inbox/turn_request.json` — входящее состояние мира / ход;
- `outbox/turn_complete.json` — ответ агента с командами и изменениями;
- Вся обработка выполняется синхронно через мост с нулевым загрязнением песочницы.
